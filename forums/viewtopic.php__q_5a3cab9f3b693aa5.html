by stimarco on Tue Nov 10, 2009 11:13 am

Hi Helene,

There are a few programs which will find this out for you. Windows comes with a standard network tool called "ping", but you'll need to use the command prompt to get to it. (NOTE: You'll need to know the IP Address of the computers you want to test. I recently wrote an FAQ on this subject here.)

On one of the Hold down the Windows key and press "R". (Or go to the Start Menu and select "Run...") In the box that appears, type "cmd" and press return. You should now see the Windows Command Shell. (Also known as a "Command Line Interface", "CLI" or "Command Prompt". This is how computers were used before icons and pointers became fashionable.)

You can now type instructions for the computer to perform. The "ping" instruction is one such. It sends a test message to another computer on the network and reports how long it took for the message to get there. (It usually sends a batch of test messages rather than just the one as there are many reasons for a network message to be delayed; the average of the results will be the most accurate measurement.)

So, assuming you're doing all this at one of the PCs you want to play the game on, you can use Ping to send a test message to another PC you want to play with. If the other PC is at IP Address 192.168.0.1 (for example), you'd type the following:

ping 192.168.0.1

The ping command will send its test messages and report how long each round-trip took. The result is usually measured in milliseconds. For example, here's what pinging my broadband router returned:


64 bytes from 192.168.0.1: icmp_seq=3 ttl=64 time=1.270 ms
64 bytes from 192.168.0.1: icmp_seq=4 ttl=64 time=1.221 ms
64 bytes from 192.168.0.1: icmp_seq=5 ttl=64 time=3.154 ms
64 bytes from 192.168.0.1: icmp_seq=6 ttl=64 time=6.677 ms
64 bytes from 192.168.0.1: icmp_seq=7 ttl=64 time=2.310 ms
64 bytes from 192.168.0.1: icmp_seq=8 ttl=64 time=1.269 ms
64 bytes from 192.168.0.1: icmp_seq=9 ttl=64 time=1.203 ms


The important bit is the "time=xxxx" at the end of each line. This is the length of time it took the router to acknowledge the "ping" message. As you can see, it's not a fixed value. (I used a wireless network for this test. Interference from other wireless networks can cause minor variations in ping times.)

For comparison, when I ping the Small Rockets website (http://www.smallrockets.com), I get this:


64 bytes from 69.10.132.242: icmp_seq=1 ttl=49 time=231.488 ms
64 bytes from 69.10.132.242: icmp_seq=2 ttl=49 time=230.245 ms
64 bytes from 69.10.132.242: icmp_seq=3 ttl=49 time=230.460 ms
64 bytes from 69.10.132.242: icmp_seq=4 ttl=49 time=230.101 ms
64 bytes from 69.10.132.242: icmp_seq=5 ttl=49 time=230.316 ms


(The "69.10.132.242" is the IP Address of the computer the website lives on. It's what the "www.smallrockets.com" part of the web address is converted to behind the scenes.)

As you can see, that's quite a difference.

If your ping messages are taking a substantial fraction of a second over a local network, rather than the internet, there may be a problem which needs rectifying. Unfortunately, there's not much I can do about that!
