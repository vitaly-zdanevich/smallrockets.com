Re: [RAS2] Diary Entry #10

by stimarco on Fri Apr 23, 2010 4:36 pm

Right, this is my last post on the subject...


jonathan wrote:
OS X is derived from BSD, but the BSD code has nothing to do with the FSF. BSD is a derivation of an actual UNIX distribution.


This is really nit picking seems to me.


OS X is a direct descendant of "NeXTSTEP", which dates back to 1989. The kernel is a Mach design; bits of BSD were added to the mix too. 1989 is the same year BSD began to be "free" in any way and was still known as "BSD Unix". (This also predates Linux's first appearance by two years.) GCC didn't get rolled into BSD until 1994, by which time the NeXTSTEP stuff was already a long way away from the more common BSD releases. OS X's internals bear very little resemblance to the mainstream BSD releases.

OS X is derived from that, and is closed source.
The kernel—known as "Darwin"—is, and always has been, open source.

Apple bought NeXT, the OS, Steve Jobs and all. OS X is an evolution of NeXTSTEP, not a ground-up rewrite. The API even retains the same "NS" prefix for most of the Cocoa object frameworks.

All Apple has ever cared about is the user experience. The user is king, not the programmer, so Apple removed certain freedoms from developers in order to ensure a more consistent user experience for their customers. This is the exact opposite to the FSF and Microsoft approaches, which both place developers at the top of the food chain.

MS is a developer tools and technologies company first and foremost; Windows is just a convenient platform for said technologies, while Microsoft Office acts as their flagship demonstrator application suite.

The FSF goes even further and actively insults any user who dares to fail to read all the documentation for an application, and commit it to memory. Never mind that any half-decent user interface shouldn't even need a bloody manual, let alone an expensive long-term support contract.

This is reason enough for me to dismiss the FSF's value to the IT industry: End users are now the point of computers. This wasn't the case in the 1970s, when the very notion of a "consumer PC" was the stuff of science fiction, so Unix was an acceptable solution to the problems of the day. But this is no longer the case today. When the only sensible way to make money from your application is to charge for support, where's the incentive to make it easy to use? This is just plain wrong for 21st Century IT.

Apple have the right of it, I think. Even Microsoft have made moves in this direction in recent years. Their XBox360 and Windows Phone 7 platforms are just as closed and controlled as the iPhone and iPad.


But it isn't because over time it has evolved. Perhaps not in a 'planned' fashion you seem to prefer - but it has. And its been there first with lots of tech. Even as recently as 64 bit - it was there first. Terra-byte drives. It runs the majority of super computers - so I'm not sure why you are so worried about scalability for the future.


Unix wasn't invented by the FSF. It predates the FSF by almost 15 years. That's plenty of time for a commercial OS to grow and mature into a stable platform. For a movement that hates Apple and Microsoft so much, they seem to spend an awful lot of time copying their user interfaces. (Badly, I might add. They still do not understand good UI design.)

I'm not saying being open source doesn't have some plus points. It's a very good fit for those situations where the end users are also programmers. It's very easy for a university researcher to hack together a new driver for their strange new hardware, for example. And in this use case, I'd agree that a platform like GNU/Linux is a good fit.

But that very openness is also its Achilles' heel: the code is often not that good, and proper design tends to be secondary. Effective QA is damned-near impossible unless you just give away the source. (The FSF hardly needs the GPL for Linux: it's "self-open-sourcing" due its fragmented nature.)

The very people attracted to the FSF are also the very same people who really shouldn't be allowed to write a Human Interface Guidelines document. Programmers generally don't make good interface designers. But there's no "Free Interface Foundation" movement. Nor is there a "Free Graphics Foundation" movement. With the FSF, it's all about the code, all the code, and nothing but the code.

Furthermore, the FSF are trying to displace a much older concept: Public Domain. If I want to give my stuff away to the world in order that all may benefit, Public Domain is a far better choice than something like the GPL. I don't care if I'm credited in each and every implementation. The point is that it's out there. No strings attached.
