Geometrian wrote:What was broken with Vista? I have Vista, and the normal one worked fine...


Unfortunately, different PCs seem to produce different results. We've had reports of our games running fine on some Vista-based PCs, while others -- sometimes even with the same hardware! -- just fall over or point-blank refuse to run them.

We are also well aware that our games simply don't understand the concepts of Administrator Users, Power Users and all the other security features introduced by the switch away from the MS-DOS-based versions of Windows (95, 98, 98SE an ME), so they try and write data into places that Windows 2000, XP and Vista really don't want them to.

Until Vista, all versions of Windows gave users maximum rights and privileges *by default*; security was essentially something you had to switch on and enable piece by piece -- always assuming you knew how. Although XP and 2000 don't let you see inside the "My Documents" folders of other users who share the computer, you're otherwise kept on a very long leash. This gave our games a reprieve: they could write to the Program Files folder (where the games are installed) with impunity.

Vista changes all this.

All the fancy security stuff is switched on by default. Users aren't given Administrator rights by default: they get normal user rights instead (as they should have been given from day one!) Most importantly: programs are required to behave impeccably. One step out of line and Vista begins to act like an especially paranoid survivalist, treating the program like a pariah.

All this is in place to make Windows Vista much more secure than its predecessors. And, to be fair, it's a huge improvement on the Swiss cheese approach to security that was Windows XP. It really does make it that bit harder for viruses, spyware and other naughty programs to get a foothold on your computer too. But it plays merry hell with games. Games are now supposed to save in a dedicated "Saved Games" folder inside your "Documents" folder. Our games don't do this: they try and save inside their install folder. Vista *hates* that. Which is why Microsoft added "Compatibility" features that tell Vista to pretend it's an older version of Windows while the program is running. It sometimes works, but it's clearly far from a perfect solution.

So Jon is building a completely new set of tools -- new 3D graphics engine; new networking engine; new GUI engine; you name it -- and plans to convert all our existing games to use the new system once it's ready. (It won't be too long now either. Honest! )

It's not _just_ about graphics. Jon's core experience is in the graphics and physics fields, so there's been a huge learning curve for some of the other components. But, once it's done, it'll support games for years to come and Jon will (hopefully) be able to afford to bring other programmers on down the line to maintain it and keep it all up-to-date.

The key obstacles have been time and resources. Jon isn't just building a new 3D graphics engine. He's also building a GUI library, an input library, an OS abstraction layer (so the game can run on other platforms more easily), a networking library, an audio library and more. The intention is for future games to be platform-agnostic, so they can be built more easily for, say, Mac OS X, XBox360 and so on.

On top of that, he's also had to build the workflow tools such as a mission and terrain editor, importers for the 3D modelling apps artists like to use, compression tools so that the game can be downloaded reasonably quickly, unit tests to ensure the code is solid, as well as physics support, an AI framework, new website and server-side components... the list is *huge*.

This is all in addition to maintaining the existing website, designing RAS 2 (and other sequels), as well as supporting existing users. Like myself, Jon's been in this industry since the 8-bit days of the ZX Spectrum and Commodore 64, so he's a bit of an all-rounder. Nevertheless, taking on a project like this was a lot to take on. Renderware Graphics -- the first successful 3D graphics middleware library -- took ten people more then three years to build. Jon's doing a hell of a lot more, but single-handed.
